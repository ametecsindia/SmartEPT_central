1 · What's solid (the foundation)

So the findings sit in context — these are genuinely well-implemented and I verified them in code:

AreaWhat's right
Tenant isolationClient portal scopes every query through ->tenant(); invoice/quote print routes check tenant_id against the logged-in user — no IDOR (a client cannot open another company's document).
Payments ledgerrecordPayment() is idempotent per payment_id, runs in a DB transaction with lockForUpdate, provisions on the first money/credit event, and settles when the balance is covered. Partial/credit instalments supported.

2 · Bugs & edge cases found

B1Licence .lic hardcodes 7-day grace, ignoring the licence's real graceP2BugLicence engine
Where LicenseSigner::sign() — the signed payload sets 'grace_days' => 7 literally, but the licences row has its own grace_days (trial = 0).
Effect A trial (or any non-7-day) licence issued as a .lic would grant 7 grace days on the product side. Low blast radius (trials rarely get .lic), but it's a correctness bug.
Fix Use $licence->grace_days in the payload. ~2-minute change.
B2AMC (perpetual) expiry has no renewal reminderP2Bug / gapClient + Admin
Where RunDunning reminds on subscription & trial expiry only. The AMC machinery exists (renewAmc(), amc_expires_at, amcActive()) but nothing emails a perpetual client before their AMC lapses.
Effect With the new v2 Perpetual model this matters more: perpetual clients silently drop out of updates/support when AMC expires, with no nudge to renew — lost recurring revenue.
Fix Add AMC reminders (T-30/7/1/0 on amc_expires_at) to the dunning command, mirroring the renewal path.
B3Failed-payment webhooks are not handledP3GapPayments
Where WebhookController handles only payment.captured (Razorpay) and checkout.session.completed (Stripe). payment.failed/charge.failed are ignored.
Effect A failed payment leaves the order silently unpaid with no signal to admin or client — no retry nudge, no "your payment didn't go through" email.
Fix Record failed attempts + notify (admin panel flag + optional client email). Pairs with a small failed-payment dunning step.
B4Stripe path uses full markPaid vs Razorpay's ledger recordPaymentP3ConsistencyPayments
Where Stripe webhook & redirect call markPaid() (settles the whole order); Razorpay uses recordPayment() (ledger). Today Stripe checkout always equals the full balance, so it's correct — but the two paths are inconsistent.
Effect If a Stripe payment ever represents a balance/partial on a credit order, markPaid would over-settle. Latent, not currently triggered.
Fix Unify on recordPayment($order, $order->balance(), …) so both gateways share one ledger door.
B5No unique index on webhook_events(gateway, event_id)P3RobustnessPayments
Effect Concurrent redeliveries of the same event can create duplicate rows (the payment ledger's payment_id idempotency still prevents double-charging, so it's harmless today).
Fix Add a unique constraint so duplicates are rejected at the DB, tightening the idempotency guarantee.

3 · Security & hardening

S1Payment & mail secrets stored in plaintext at restP1SecuritySuper Admin
Where settings table holds razorpay_key_secret, stripe_secret_key, both webhook secrets, mail_password, interakt_api_key as plain values (the UI masks them with ••••, but the DB stores plaintext).
Effect A database dump, backup leak, or read-only DB access exposes live payment keys — enough to create charges/refunds on your gateway accounts.
Fix Encrypt secret settings at rest (Laravel Crypt / an encrypted cast on those keys), or move them to .env/a secrets manager. One-time migrate to re-encrypt existing values.
S2No 2FA / MFA on the admin consoleP1SecuritySuper Admin
Where Admin\AuthController — password-only login for super/sales/support.
Effect A single leaked admin password exposes all tenant billing, licences, gateway secrets and settings. For a money-handling console this is the highest-value hardening.
Fix Add TOTP 2FA (authenticator app) at least for the super role; ideally all admin staff.
S3Long admin session windowP2SecuritySuper Admin
Where config/session.php — lifetime 120 min, expire_on_close=false.
Fix Shorten the admin idle lifetime (e.g. 30–45 min) and expire on browser close; optionally an IP allowlist for the super role.
S4Public pay page unthrottled; fingerprint auto-binds to first callerP3SecurityClient / Licence
Pay page /pay/{number}/{token} is protected by the 20-char HMAC token but has no rate limit — add a throttle to blunt enumeration.
Fingerprint A licence binds its server_fingerprint to the first server that phones home. That's the intended node-lock, but make sure an admin "reset server fingerprint" action is available (via licences/{id} update) and documented for legitimate server moves.

4 · Missing / improvements (by area)

Super Admin

  • M1 · Webhook failure visibility — webhook_events.error is stored but never surfaced. Add a "failed webhooks" panel + alert so a silent gateway issue is noticed.
  • M2 · Audit export/retention — audit_logs is append-only (good). Add a periodic export + retention policy for compliance.
  • M3 · GST e-invoicing (IRN + signed QR) — mandatory above the turnover threshold in India; not implemented. Roadmap item as revenue scales.

Admin (sales / support)

  • M4 · Failed-payment dunning — retry reminders for failed/abandoned checkouts (pairs with B3).
  • M5 · Support SLA — tickets are threaded (support_ticket_messages); add SLA timers + a notification to the support desk on every new client ticket (confirm it's wired).
  • M6 · Export-of-services (USD) — USD invoices carry 0% GST; ensure LUT / zero-rated export handling + foreign-remittance (FIRC) notes for clean compliance.

Client portal

  • M7 · Self-serve storage top-up — at 100% screenshots pause; today the client must contact you. Add a "buy more storage" purchase in the portal.
  • M8 · Auto-renewal / card-on-file — renewals are manual (reminder → click). Optional for India B2B, but Razorpay/Stripe subscriptions would cut churn on Cloud.
  • M9 · Data-subject request path — the purge flow correctly keeps billing; add an explicit client data-export / deletion-request path for privacy asks.

Engineering

  • M10 · Security tests — the 6 tests cover the money/GST path well, but add tests for webhook signature verification, licence node-lock & seat-cap, admin role enforcement, and cross-tenant IDOR.
