Honest scope note — what was already built

The original roadmap listed a long "sales-ops gaps" line. A read of the live code (and the 27-Jul deep-scan) showed most of it already exists and was deliberately not rebuilt: partial payments (the locked payment ledger), refunds (GST credit notes), per-deal discounts (the Coupon system, applied on signup / portal / admin quotes), renewal & trial dunning, and quotations. So this delivery is tightly scoped to the genuine gaps.

What was built

1 · Grandfather rule — migrate at renewal, with a price cap DONE

Every existing (pre-v2) non-trial licence is flagged pricing_model = legacy and its ex-GST last-paid subtotal is snapshotted as legacy_baseline_inr. On its first renewal the quote is computed on the new user-based model but capped so the bill can't rise more than pricing_grandfather_cap_pct (default 20%) above that baseline — shown as a visible "Loyalty price protection" line before GST. After that renewal the licence flips to v2 and renews at full rate thereafter.

Files: BillingService::createRenewalOrder (cap) + provisionIfNeeded (flip) · Licence model · migration.

2 · Client PO number DONE

An optional purchase-order number is captured on the admin New Order / Quote screen and the client-portal Buy flow, stored on the order, and printed on the quotation / proforma.

Files: orders.po_number (migration) · Order model · BillingService (createOrder / setup) · BillingApiController + PortalApiController validation · console.blade New-Order form · quote-print.blade.

3 · Quotation / pay-link expiry DONE

Every new order / quote gets valid_until = today + quote_validity_days (default 7). An expired pay page shows a friendly "quotation has expired — contact sales" message, and both the Razorpay and Stripe payment starts refuse with HTTP 410. A live credit order (already part-paid / provisioned) always stays payable. The quotation is relabelled "Quotation / Proforma Invoice" and prints its validity date + PO.

Files: orders.valid_until (migration) · Order::isExpired() · CheckoutController (show + Razorpay + Stripe) · checkout.blade · quote-print.blade.

4 · Legacy Plans-table cleanup DONE

The admin console Plans table and editor dropped the obsolete Perpetual ₹/device and Server-licence ₹ columns (pre-v2) and now show the v2 by-user perpetual bands instead. The save payload no longer sends the legacy fields (the update endpoint already treated them as optional, so nothing breaks).

Files: console.blade (Plans table, edit-plan form, savePlan).

Notes & deliberately out of scope

  • The grandfather cap applies to subscription (Cloud) renewals. Perpetual customers renew via AMC, which is unchanged — a perpetual-AMC grandfather rule can follow if you want one.
  • The admin New-Order form still lists legacy Core / Professional / Enterprise plan options (a pre-v2 leftover, separate from this pricing-finalise scope). Flagged as a small follow-up cleanup.
